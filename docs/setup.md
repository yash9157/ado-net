# 1. Create the API

This step creates the web project and connects it to SQL Server. Run commands from a new, empty folder.

## Create the project

```powershell
dotnet new webapi --use-controllers --no-https -f net10.0 -n StoreApi
cd StoreApi
```

Remove the template's WeatherForecast example if it exists. Then install the packages used in this tutorial:

```powershell
Remove-Item WeatherForecast.cs, Controllers/WeatherForecastController.cs -ErrorAction SilentlyContinue
dotnet add package Microsoft.EntityFrameworkCore.SqlServer --version 10.0.12
dotnet add package Microsoft.EntityFrameworkCore.Design --version 10.0.12
dotnet add package Microsoft.AspNetCore.Identity.EntityFrameworkCore --version 10.0.12
dotnet add package Microsoft.AspNetCore.Authentication.JwtBearer --version 10.0.12
dotnet add package Microsoft.AspNetCore.OpenApi --version 10.0.12
dotnet add package Microsoft.Data.SqlClient --version 7.1.0
```

Your `.csproj` should have these package references:

```xml
<Project Sdk="Microsoft.NET.Sdk.Web">

  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
  </PropertyGroup>

  <ItemGroup>
    <PackageReference Include="Microsoft.AspNetCore.Authentication.JwtBearer" Version="10.0.12" />
    <PackageReference Include="Microsoft.AspNetCore.Identity.EntityFrameworkCore" Version="10.0.12" />
    <PackageReference Include="Microsoft.AspNetCore.OpenApi" Version="10.0.12" />
    <PackageReference Include="Microsoft.Data.SqlClient" Version="7.1.0" />
    <PackageReference Include="Microsoft.EntityFrameworkCore.Design" Version="10.0.12">
      <IncludeAssets>runtime; build; native; contentfiles; analyzers; buildtransitive</IncludeAssets>
      <PrivateAssets>all</PrivateAssets>
    </PackageReference>
    <PackageReference Include="Microsoft.EntityFrameworkCore.SqlServer" Version="10.0.12" />
  </ItemGroup>

</Project>
```

Put the classes shown on later pages in this layout. You only need to create the folders and C# files as you reach them; migration files are generated by a command in the final step.

```text
StoreApi/
  Program.cs
  appsettings.json
  appsettings.Development.json
  Models/Product.cs
  Data/StoreDbContext.cs
  Data/SqlConnectionFactory.cs
  Data/Migrations/                 (generated later)
  Contracts/RegisterRequest.cs
  Contracts/LoginRequest.cs
  Contracts/TokenResponse.cs
  Contracts/CreateProductRequest.cs
  Contracts/ProductResponse.cs
  Repositories/IProductStoredProcedureRepository.cs
  Repositories/ProductStoredProcedureRepository.cs
  Controllers/AuthController.cs
  Controllers/ProductsController.cs
```

Replace the template `Program.cs` with the version on the [login page](authentication.md). It references classes added later, so compile the project after you have copied all classes.

## Start SQL Server

On Windows, LocalDB is the shortest way to follow the example:

```powershell
sqllocaldb create AdoNetInterview
sqllocaldb start AdoNetInterview
```

If the instance already exists, skip `create`. If you use another SQL Server, change the connection string below.

## Configure the database and JWT

Replace `appsettings.json` with:

```json
{
  "ConnectionStrings": {
    "StoreDb": "Server=(localdb)\\AdoNetInterview;Database=StoreInterviewDb;Integrated Security=True;TrustServerCertificate=True;"
  },
  "Jwt": {
    "Issuer": "StoreApi",
    "Audience": "StoreApiClient"
  },
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.AspNetCore": "Warning"
    }
  },
  "AllowedHosts": "*"
}
```

Create or replace `appsettings.Development.json` with a demo JWT signing key:

```json
{
  "Jwt": {
    "Key": "development-only-demo-key-change-before-deployment-2026"
  },
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.AspNetCore": "Warning"
    }
  }
}
```

The demo key is only for local Development. An actual deployment must set its own private `Jwt__Key` (at least 32 bytes) through configuration.

The [migration explained in step 4](stored-procedures.md) creates the database objects when applied in the final step. You do not need to run a separate SQL setup script.
